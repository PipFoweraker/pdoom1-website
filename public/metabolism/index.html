The metabolism of this project

Every recurring beat we run, on one page: how fast it turns, when it fires, and — for every single number — which file it was read out of. Nothing here is typed in. This page is generated by scripts/generate-metabolism.py from the cron expressions, config files and ledgers that actually run, and a CI check fails the build if the page and its sources ever disagree.

Where a cadence is genuinely unknown, it says unknown. A gap in the picture is information; a plausible-looking guess would not be.

18 live cycles · 2 unquantified · 5 parked · 37 sources read

The epicycles

One ring per distinct period, log-spaced: fastest innermost, slowest outermost. Every ring’s radius is computed from its period, so the picture cannot drift from the table below it. Twelve o’clock is the start of each ring’s period; a marker sits at the point in the cycle when that job fires, which is why markers stacked along one radius are jobs that fire at the same instant. Click any marker to jump to its row.

Reading the map

  • cross-repo
  • declared clock
  • repo automation
  • upstream (mirrored)
  • hollow: period known, firing time not published

An arc instead of a dot is a window: the event lands somewhere inside it, and nobody has published where. The arc covers the whole window rather than asserting a moment.

Dots stacked outward along one radius fire at the same instant. That is a real collision, not a drawing artefact.

The amber disc at the centre is the deploy path. It is a latency, not a period, so it is drawn as a disc rather than a ring: pushing to main is what triggers it, not a clock.

The dashed outer ring holds cycles whose length nobody has published. It is drawn outside everything known and is deliberately not to scale.

Named periods, in seconds, used ONLY to place rings on the diagram. `monthly` is the mean Gregorian month (365.2425/12 days); no calendar claim is made by it.

The cross-repo rhythm

Triumvirate metabolic cycle — pdoom1 -> pdoom-data -> website. This repository is the publisher, never the source: it reads pdoom1, never the reverse. Our leg is at AGREED-PER-LEG on the ladder PROPOSED → AGREED-PER-LEG → ACTIVE. The rule itself lives upstream at pdoom1/docs/TRIUMVIRATE_METABOLIC_CYCLE.md; this repo holds a declared mirror with a pointer, because pdoom1 publishes no artifact for it.

Our leg (Hop B -- monthly publication): after each Epoch Friday (E+1..E+4). It fires by human memory — There is no machine signal on Epoch Friday. The proposal sanctions manual-first for Aug-Oct, so this is the acknowledged exception, not a violation -- but the leg's reliability is a person remembering, and the page says so.

— League notes do not exist as an artifact in pdoom1 -- half the monthly pull has nothing to pull. This repo will not invent them.

— public/blog/post.html cannot render tables, and release bodies contain them; reshaping is the publisher's job, not a renderer bug.

pdoom-data -> website (countdown milestones) (pending upstream data): The fourth edge the proposal reserved, now open: public/data/clocks.json reads milestone dates direct from pdoom-data#38. Outside Hop B.

pdoom1 -> website (calibration artifact) (requested, not shipping): A fifth edge: pdoom1#994 asks the game to attach calibration.json to each release. The game leads calibration; the website only derives it. One arrow, not a new hop.

The check is the freshness guarantee instead: this page cannot be more than one merged pull request away from its sources.
