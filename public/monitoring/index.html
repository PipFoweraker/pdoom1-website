Instrument panel

One indicator per source. Each one is derived from a file that some workflow in this repository actually writes, and each one refuses to show you a number when the file behind it has stopped moving.

This is a developer surface, not a status page for players. It is the sibling of /metabolism/, which maps every recurring cycle this project runs. That page answers what is supposed to happen and how often; this one answers what actually landed on disk, and how long ago. Neither is a promise to anybody outside the repository. If you are looking for whether the game is up, the honest answer lives on /leaderboard/ and in the releases themselves.

How to read this page

There is deliberately no overall health score. A single percentage over eight unrelated sources reads 100% while three of them are dead, which is what this page used to do. Every box below stands or falls on its own; re-aggregating is a decision for later, once each atom is individually trustworthy.

CURRENT — the source was written inside this page's declared window, so its contents are shown.
STALE — the source is real and readable and too old. No value is shown, only its age.
UNKNOWN — the source could not be read, or carries no timestamp. Unknown is not the same as fine.
NO WRITER — nothing scheduled writes this file at all, so no age of it can mean anything.

What this page cannot tell you

  • A fresh file is not a working system. Every box above measures when a file was last written, and then what that file says about itself. A workflow that runs on time and writes a confidently wrong answer looks identical to one that is right.
  • The automation ledger is the acting party's self-report. Each job writes its own "I ran, and it went well" line at the end of its own run. A job that dies before reaching that step logs nothing at all, so an absent entry and a job that was never scheduled are the same bytes. A check should take its observation from inside the system under test, never from the actor's report that it acted; this one cannot.
  • A parked workflow and a broken one look the same from here. When a schedule is deliberately removed, the file it wrote correctly stops moving and this page correctly calls it stale. That is the right verdict and the wrong explanation. The reason always lives in the header comment of the workflow in .github/workflows/, and there is no way to read it from a browser.
  • These files are what was last deployed, not what is in the repository. Everything above is fetched from this site, so a commit that has not been rsynced yet is invisible here, and a file excluded from the deploy is invisible forever.
  • The clock at the bottom is your browser's. Every age on this page is computed against it. A wrong local clock makes every box wrong in the same direction, which is precisely the failure that is hardest to notice.

What was removed, and why

  • The Health Score percentage. It divided one file's passed-checks by its total-checks and presented the result as the health of the site. Its source had not been written in weeks, so it read a steady green 100%.
  • The "Website Status: Online" card. It fetched this site from the browser that had already loaded this page. If the site were down you would not be reading the card, so it could only ever say Online. A self-fetch measures nothing.
  • The "GitHub Integration: Connected" card. It reported "Connected" whenever a committed JSON file on this site contained a repository_stats key. That is a statement about a file in this repository, not about GitHub. Whether the data derived from GitHub is current is now the Release data box, which says so honestly.
  • The "Manually Trigger League Rollover" button. It ran no rollover. It opened a confirm dialog and then an alert telling the reader to go and use GitHub Actions. A control that does not do the thing written on it is a lie with a cursor.
  • The weekly-league box. Its numbers duplicate /leaderboard/, which owns them. Whether the rollover job is still logging runs is a genuine developer signal and is kept, in the automation ledger box.
