# Gate 4 proving runs — `(weekly-2026-w30, L3)`

Captured 2026-08-01 from the live score API.

## What this is, and why it is not a loss

Three runs played by Pip on the morning of **2026-07-30** to satisfy
**[Gate 4: PROVEN BUILD]** — the requirement that a human plays the artifact that ships,
not the thing we meant to ship. Two on `v0.13.2`, one on `v0.13.1`, all on ladder epoch
`L3`.

They sit on seed `weekly-2026-w30`. The league opened the following evening on
`weekly-2026-w31`, because **Pip ruled that the proving runs should not open the board**
(2026-07-31). The website does not filter a live board — removing entries is editing
standings — so the only honest way to exclude them was for the league to open on a
different seed.

**So these are orphaned by DESIGN, not by accident.** Nothing was lost, nothing failed,
and no player is affected. The distinction matters because
`scripts/check-board-liveness.py` cannot tell "excluded by ruling" from "lost by mistake";
it can only tell "published" from "not published". Placing the capture here is how the
ruling gets recorded in a form the tooling reads: the archive is the **acknowledgement
register**, and a board that appears here is known history rather than a live incident.

Without this file the liveness check would have gone red **every hour**, forever, about a
situation everyone had already agreed on — which is exactly how a guard trains people to
ignore it.

**CORRECTED 2026-08-06.** This line previously read *"The lab names are generated by the
game; both belong to Pip."* The second half is right. The first half was an assumption I never
checked, in a file whose entire purpose is accurate provenance.

The game does generate lab names, from `godot/scripts/ui/pregame_setup.gd:29-45` --
`prefix + topic + suffix`, e.g. `Applied` + `AI Safety`. Both names here are assemblable from
those lists. But the field is an editable input pre-filled with a suggestion, so even a matching
name means "the game proposed it and the player kept it", not "the game produced it".

And elsewhere on the live board sits **`Notkilleveryone Inc`**, which cannot come out of that
generator at all -- `Inc` is in no suffix list and `Notkilleveryone` in no topic list. Pip wrote
it. He said so, and the source agrees with him.

So: these names belong to Pip, and how much of each one he typed is not recorded anywhere. That
is the honest statement.

*Method note, because it nearly went wrong twice.* Grepping the game for the assembled strings
returns **zero files** for every name, including the ones the generator can produce -- the
components are in the source, the finished string never is. That result reads exactly like "the
game did not make these" and is an artefact of the instrument. Only reading the word lists
separates a generated name from a typed one. Filed as the near-miss class in
pdoom1-website#268.

Note the board legitimately spans **two builds**. That is the build-vs-ladder split working
as designed — the build version is not part of the board key, so a patch bump cannot fork a
board.

## Rules

**Never edit these files. Never re-stamp their version or seed.** They are a dated
observation of what the API held. Re-stamping would assert that these runs belong to a
board they were not played on, which is the specific lie the ladder split exists to
prevent.

Unlike the 2026-07-29 capture — which recorded 27 genuinely stranded scores from six real
players — this one records a deliberate exclusion. Both are permanent; only one was a
failure.
